Önce amaç, sonra araç

Git gerekli mi, nasıl kullanılır, hangi alışkanlıklar işe yarar?

Git’i komut ezberi olarak değil, çalışma hafızası olarak düşünün: ne değişti, kim değiştirdi, neden değiştirdi ve güvenle geri dönebilir miyiz sorularına cevap verir.

Gerekli mi? İyi alışkanlıklar Gerçek repo turu

Karar ölçütü

Git her iş için şart değil, ama çoğu ciddi işte erken rahatlatır

Kullanın

Git anlamlıdır

  • Bir dosyanın birden fazla sürümü olacaksa.
  • Bir projede birden fazla kişi çalışacaksa.
  • Deneme yapıp ana çalışan hali bozmamak istiyorsanız.
  • Bir rapor, kod, devre ya da veri analizinin geçmişi önemliyse.
  • Yayınlamadan önce değişiklikleri gözden geçirmek istiyorsanız.
Basit tutun

Git gereksiz olabilir

  • Tek seferlik, atılacak bir dosya üretiyorsanız.
  • Proje yalnızca büyük ikili dosyalardan oluşuyorsa ve geçmiş gerekmiyorsa.
  • Gizli veri, şifre ya da kişisel bilgi ayıklanmadan depoya girecekse.
  • Ekibin önce klasör düzeni ve dosya adlandırması çözülmemişse.

Gerçek kullanım

İnsanlar Git’i günlük iş akışı olarak kullanır

Planla

Issue açılır: yapılacak iş, hata, soru ya da karar görünür hale gelir.

Ayrı çalış

Branch açılır: deneme ana çalışan sürümü bozmaz.

Kaydet ve açıkla

Commit küçük bir değişikliği, nedenini anlatan mesajla kaydeder.

İncele ve birleştir

Pull request üzerinden diff okunur, yorum yapılır, uygun olunca merge edilir.

İyi alışkanlıklar

İyi Git kullanımı teknikten çok ekip alışkanlığıdır

Geçmiş

Küçük ve anlamlı commit

Bir commit bir fikri taşısın. “final”, “son”, “düzeltme” yerine neyin neden değiştiğini yazın.

Güven

main çalışır kalsın

Deneyler branch’te yapılır. Çalışmayan kod, bozuk rapor ya da yarım dosya ana hatta alınmaz.

İnceleme

Pull request küçük olsun

Küçük PR okunur, tartışılır ve hızlı birleşir. Büyük PR çoğu zaman kimsenin gerçekten okumadığı değişikliktir.

Güvenlik

Şifre ve gizli veri yok

API anahtarı, Wi-Fi şifresi, özel veri ve kişisel bilgi depoya girmez. Örnek ayar dosyası kullanın.

Dosya düzeni

Üretilen dosyayı değil kaynağı izleyin

Derleme çıktısı, geçici dosya ve büyük veri için `.gitignore`, gerekirse Git LFS ya da ayrı depolama kullanın.

Ekip kültürü

Review kişiye değil işe bakar

Yorumlar somut, nazik ve satıra bağlı olsun. Amaç hata yakalamak kadar ortak standart oluşturmaktır.

Ders mesajı

Öğrenciye verilmesi gereken ana fikir

“Git, kod yazanların kullandığı karmaşık bir araç değil; ciddi bir projede değişiklikleri güvenle yönetmenin yoludur. İyi kullanırsanız hata yapmayı daha az korkutucu, ekip çalışmasını daha görünür yapar.”
