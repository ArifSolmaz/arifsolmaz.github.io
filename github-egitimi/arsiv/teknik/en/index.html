1 · VERSION CONTROL

Git keeps your code's timeline

Git is a free, open-source, distributed version control system. It stores snapshots of committed project states. Saving a file does not automatically create a commit.

?

Inspect

Which line changed, who changed it, and when?

Find the bug

Find which change introduced the bug.

Revert

The value of version control: tracking changes over time. Each commit is a snapshot, so you can inspect, find bugs and roll back.

1 · NOT THE SAME THING

Git ≠ GitHub

Git

A tool on your computer

Tracks changes and keeps local history. No internet needed.

git commit · git log

GitHub

A platform on the web

Hosts Git repositories: teamwork, code review, backup and portfolio.

Pull request · Issues · Actions

This is the most common confusion. Git is the local tool; GitHub is the service that hosts repositories online. GitLab and Bitbucket also use Git.

4 · SSH

SSH authentication with a key pair

How it worksSSH verifies possession of the private key using the public key on GitHub. The private key is not sent. This is separate from signing commits.
SSH authentication proves possession of a private key. Add only the public key to GitHub. Using SSH does not automatically sign commits, and repository write permission is a separate check.

4 · CREATE A KEY

Generate the key, add it to GitHub

terminal
$ ssh-keygen -t ed25519 -C "you@example.com"
Enter file in which to save the key (~/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):

# macOS: copy the public key to the clipboard
$ pbcopy < ~/.ssh/id_ed25519.pub
Key filesid_ed25519 is the private key; id_ed25519.pub is the public key. Only the public key goes to GitHub.
  1. Press Enter for the path: ~/.ssh/id_ed25519
  2. Choose a passphrase to protect the private key
  3. Copy the .pub file
  4. GitHub: Settings → SSH and GPG keys → New SSH key → paste → Add SSH key
All examples use Ed25519. Check for existing keys before choosing a path. A passphrase protects the private key, and an agent reduces repeated entry. Copy only the .pub file: pbcopy on macOS, clip in Git Bash, or display and copy it on Linux. No installation takes place in class.

5 · GIT INIT

Turn a folder into a repository and link it

before a remote exists
$ cd path/to/demo-repo-2
$ echo "# Demo Repo 2" > README.md
$ git init -b main
$ git add README.md
$ git commit -m "First commit"

$ git push origin main
fatal: 'origin' does not appear to be a git repository
Why the error?The local repository has no address called origin.
the fix
# create an empty repo on GitHub, copy its SSH URL
$ git remote add origin git@github.com:username/demo-repo-2.git
$ git remote -v
git init -b main creates .git and selects the initial branch name main (Git 2.28+). The prepared error appears because origin has no remote URL yet; explain the solution without running it. remote -v lists fetch and push URLs.

5 · UPSTREAM

Use -u on the first push

terminal
$ git push -u origin main
Branch 'main' set up to track 'origin/main'.

# from now on the short form is enough
$ git push
$ git pull
Instructor note-u links local main to origin/main and saves it in .git/config. After that, no target needed.
Common pitfallA bare git push on a fresh repository fails. This example sets the upstream on the first push.
These examples use main. Other projects may use another name; git branch shows it. -u records the remote branch tracked by the local branch. Behavior on a first bare push can depend on configuration; naming the target makes the example explicit.

6 · LOCAL MERGE

Look first, then merge, then clean up

terminal
# 1. switch to the target branch
$ git checkout main
# 2. inspect the differences
$ git diff main feature-readme-instructions
- Setup
+ Setup: open index.html in your browser
# 3. merge
$ git merge feature-readme-instructions
# 4. delete the short-lived branch
$ git branch -d feature-readme-instructions
git diff main feature-readme-instructions shows the changes from main to the feature branch: minus is old, plus is new. Merge while on the target branch main. -d refuses to delete an unmerged branch. Teams can add review through a pull request.

8 · MERGE CONFLICT

Two different edits to the same line

quick-test
$ git merge main
Auto-merging index.html
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit.
Why does it stop?Git can't decide which line is right, so it asks you. It also happens when a file is changed on one branch and deleted on the other.
Scenario: on quick-test you changed line 2 to world; meanwhile on main the same line became there. Merging main into quick-test conflicts. A conflict is not an error, it is a question.

8 · RESOLVING

Read the markers, choose, clean up

index.html
<<<<<<< HEAD<p>world</p>=======<p>there</p>>>>>>>> main
  • <<<<<<< HEAD your branch
  • ======= separator
  • >>>>>>> main incoming branch
  1. Open the file in VS Code
  2. Keep what you want, delete the marker lines
  3. Save; stage: git add index.html
  4. Finish with a commit
terminal
$ git commit -m "Resolve merge conflict"
Check the resultAfter removing the markers, test the result; then git add and commit.
Conflict markers show two versions. Choose a meaningful final result, remove markers and test it; blindly keeping both versions is not always correct. Saving in the editor and git add are different steps. Add stages the result; commit records the resolution.

9 · UNDOING

Undo staging or the last commit

Staged by mistake

terminal
$ git add README.md
$ git reset
$ git status
modified: README.md

Your edits stay; the file just leaves staging.

Undo the last local commit

terminal
$ git reset HEAD~1

HEAD is the current commit of the active branch. HEAD~1 moves back one; your code stays on disk (--mixed).

Look at history

terminal
$ git log
commit a1b2c3d4…
Author: elif
    Add README

Newest first. Space to scroll, q to quit.

git log shows commit identifiers; git log --oneline gives a compact list. reset HEAD~1 applies here only to an unpublished local commit. For shared history, git revert <hash> records the inverse change in a new commit.

9 · MIXED VS HARD

Keeping files vs overwriting files

git reset HEAD~1git reset --hard <hash>
Staging areaUnstages changesMatches the target commit
Your code on diskKeptMatches the target commit
Risk of losing workLowUncommitted work may be lost
Warning: destructive commandgit reset --hard a1b2c3d4 makes tracked files match the target commit; uncommitted changes may be lost. Previously committed work can sometimes be recovered via reflog. For shared history, use git revert <hash>.
Hard reset can discard uncommitted edits in tracked files. Previously committed work may sometimes be recovered through reflog while references remain; do not rely on it for uncommitted work. Use revert to undo changes in shared history. No destructive command is run in class.
