WHAT IS GITHUB?

An online folder for your projects, and then some

01

A folder

Code, circuit diagram, report, photos: all in one place, online.

02

A time machine

Every change is recorded; you can always look at an older version.

03

A meeting place

Your team's to-do list, and a showcase for what you've built.

No terminal, no commands, no coding experience needed: today everything happens in the browser.

⏱ 04:00–06:00 · 2 min Think of GitHub as three things. First, a folder: your code, circuit diagram, report and photos, online, in one place. Second, a time machine: every change is saved, and you can always go back and look at an older version. Third, a meeting place: your team's to-do list, and a showcase for what you've built. Under the hood there's a recording tool called Git; programmers use it from the command line. We won't touch it today: GitHub's website and your phone are enough. Creating an account is free. [Ask: "Is it only for programmers?" No: people store circuit diagrams, reports, course notes, even 3D-printer files.]

⏱ 06:00–07:00 · 1 min Four words are enough for today. GitHub's interface is in English, and this is how you'll see these words on screen. Repository: your project's folder online; the files and their whole history. Commit: a save point, with a short note saying what changed. Issue: a task to do or a note about a bug; it gets a number. README: your project's front page; the first file anyone opening the repository reads. Don't memorize them; you'll see each one live in a minute.
⏱ 07:00–10:00 · 3 min Benefit 1: your project is never lost. Laptops die, USB sticks get lost, lab computers get wiped every night. If the project is on GitHub, none of that matters: your files are safe online. You open the same project from the school computer, from your laptop at home, from your phone on the bus, and you always see the latest version. Upload once, open anywhere. [Ask: "Has anyone lost a project or an assignment?" Hear one or two stories.] ▶ LIVE (30 s): Open your own GitHub profile on your phone and show it: the repositories on the computer are the same on the phone.
⏱ 10:00–14:00 · 4 min So how does a project get onto GitHub? It takes a minute. Elif creates a new repository: New repository. She names it, turns on Add README and clicks Create repository. Then Add file, Upload files: she drags the files in, writes a short note and clicks Commit changes. Done. Notice: it's not just code. The circuit diagram, the report, the photos: everything about the project in one place. ▶ LIVE: github.com/new → name: example-project → Add README: On → Create repository → Add file → Upload files → from the kit's example-project folder drag README.md, robot.ino, circuit.png, project-report.pdf and the photos folder → note: Add project files → Commit changes. The README.md you upload replaces the old one and shows on the repository page right away. Write the word "repository" on the board. ↺ BACKUP: If there's no internet, play the animation again and talk through the steps.
⏱ 14:00–18:00 · 4 min Benefit 2: a time machine. "It worked yesterday!" What changed? Open the file and click History. Every save is listed: who, when, and with what note. Nobody keeps this list by hand; GitHub records it automatically with every commit. Click yesterday's save and you see the change: the red line is the old version, the green line is the new one. Deniz raised the sensor threshold from 500 to 900. If needed, we can look at the whole project as it was that day. So don't be afraid to break things: every save is a way back. ▶ LIVE: example-project → robot.ino → pencil (Edit) → change THRESHOLD = 500 to 900 → Commit changes → note: Change sensor threshold → History on the file page → click this save → point at the red and green lines. Write the word "commit" on the board.
⏱ 18:00–22:00 · 4 min Benefit 3: your team's to-do list. Team tasks get lost in the group chat. On GitHub, every repository has an Issues tab: a shared to-do list. New issue: what needs doing? A title and a short description. Who's doing it? Pick someone under Assignees. Everyone sees the same list. When the task is done, Close issue: it leaves the list, but the record stays; you can find it months later. Capstone project, club project, assignment group: it fits all of them. ▶ LIVE: example-project → Issues → New issue → title: Take photos of the robot → description: On the track, in good light → Assignees: pick yourself → Create → then Close issue. Write the word "issue" on the board.
⏱ 22:00–26:00 · 4 min Benefit 4: find ready-made code and use it. We're adding a distance sensor to the robot. Instead of writing the code from scratch, we search GitHub. Which one should you pick? One with lots of stars: many people use it. One that was updated recently. One whose README has a wiring diagram and an example. The Code button, Download ZIP: the whole project downloads as one file. In the Arduino IDE: Sketch → Include Library → Add .ZIP Library... The library is installed, and the sensor works with two lines of code. If you get stuck, you can ask a question in that repository's Issues tab. ▶ LIVE: Search GitHub for "DHT sensor library" → adafruit/DHT-sensor-library → point at the stars and the latest update → in the README, point at the Adafruit Unified Sensor line (that's why reading the README matters) → Code → Download ZIP → Arduino IDE → Add .ZIP Library... → the downloaded zip → File → Examples → DHT sensor library → DHTtester. Note: the same library is in the Arduino Library Manager too; installing it from there also offers to install the other library it needs. The library and user names in the animation are examples.
⏱ 26:00–29:00 · 3 min Benefit 5: your GitHub profile is your portfolio. Elif's profile shows all her projects on one page: the four she pinned, and the green squares. Each green square is a day she worked; her effort is visible. Click a project and you see its front page: the README. What it does, the parts, how it works, a picture of the robot. Applying for an internship or a job? One line on your CV is enough: github.com/your-username. Teachers and employers don't just read about what you did; they see it. ▶ LIVE: Open your own profile: github.com/arifsolmaz → pinned repositories (Customize your pins) and the contribution graph → click one of your projects with a good README. Also show the README of the example-project we just created. Write the word "README" on the board.
