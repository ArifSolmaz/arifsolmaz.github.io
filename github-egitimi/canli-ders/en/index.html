WHAT IS GITHUB?

An online folder for your projects, and then some

01

A folder

Code, circuit diagram, report, photos: all in one place, online.

02

A time machine

Committed changes enter the history; inspect older commits.

03

A meeting place

Your team's to-do list, and a showcase for what you've built.

No prior coding experience needed: the examples are explained on slides.

⏱ 04:00–06:00 · 2 min GitHub hosts repositories containing code, circuit diagrams, reports and photos. Git records project states in commits; GitHub makes pushed history available for collaboration. Issues organize work and README introduces the project. Neither saving a local file nor editing an uncommitted file creates automatic online backup.

GLOSSARY

Four words are enough

repository

your project's folder online

the files + their whole history

commit

a save point

with a short note: what changed?

issue

a task or a bug note

it gets a number: #1, #2…

README

your project's front page

what, why, how: the first thing people read

⏱ 06:00–07:00 · 1 min Repository contains project files and version history; it can be local or hosted online. Commit records a selected project state with a message. Issue tracks a task or problem. README explains what the project does and how to use it. Relate each word to the prepared examples.

GitHub contains pushed commits. Local edits do not sync automatically.

⏱ 07:00–10:00 · 3 min An online copy can help when a laptop or USB drive fails. It contains the commits that were pushed, not every local edit. Another device can clone or pull that published history. Synchronization requires deliberate actions; GitHub is not a guarantee against every kind of data loss.
⏱ 10:00–14:00 · 4 min Read the animation's steps: create a repository, include a README, upload selected project files and commit changes. The web interface sends the committed change directly to GitHub. A local editor follows a different path: edit/save, add, commit, push. Explain that the project includes documentation and diagrams as well as code.

History records commits; saving a file is a separate action.

⏱ 14:00–18:00 · 4 min History lists commits, rather than every press of the editor's Save button. A change to the robot's sensor threshold from 500 to 900 is recorded when committed. Red and green lines compare removed and added text. Inspecting history helps identify the change that introduced a problem; undoing requires another deliberate Git operation.
⏱ 18:00–22:00 · 4 min Issues provide a shared record of a task, its context, owner and discussion. In the example, taking robot photos is a task that can be assigned and closed. Closing keeps the history available. Features and permissions can depend on repository settings; explain the prepared example.

Check the license, hardware, examples and maintenance. Stars do not guarantee quality.

⏱ 22:00–26:00 · 4 min The robot example uses an HC-SR04 distance sensor. Before selecting a library, read its license, hardware compatibility, examples, dependencies, recent maintenance and known issues. Stars express interest or bookmarking; they do not prove usage, quality or suitability. Read the installation instructions and test the example against the actual board. The animation's repository and usernames are illustrative; downloading a ZIP alone does not guarantee a working sensor.

Contribution squares count qualifying activities, not every day worked.

⏱ 26:00–29:00 · 3 min A profile can point to a small set of documented projects. A good README explains purpose, hardware, setup and results with pictures or demonstrations. Contribution squares count activities that meet GitHub's contribution rules; they do not measure all workdays, effort or skill. Project evidence is more informative than the number of green squares.

ONE PROJECT, ONE STORY

Read the robot project's journey

  1. README explains the purpose, parts and wiring.
  2. Commit records the revised sensor threshold.
  3. Push makes that commit available on GitHub.
  4. Issue tracks a task with context and an owner.
  5. The profile links to the finished, documented project.

A save in the editor, a commit and a push are three different actions.

⏱ 34:00–40:00 · 6 min Explain the prepared robot example as one continuous story. Ask students to identify what a README, commit, push and issue contribute, without opening any app. Files on a computer are not sent automatically: saving, committing and pushing are distinct. The profile communicates the project through evidence and documentation.

Online access applies to pushed commits; student benefits depend on eligibility.
