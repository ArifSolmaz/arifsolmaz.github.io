# Slayt iskeleti

Bu dosya, sunum hazırlamak isteyen eğitmen için başlık taslağıdır. Slaytları
kısa tutun; her kavramdan sonra uygulama yaptırın.

## 1. GitHub neden var?

- Aynı proje üzerinde birlikte çalışmak
- Değişiklik geçmişini görmek
- Bir değişikliği yayınlamadan önce incelemek
- Kim, neyi, neden değiştirdi sorusuna cevap vermek

## 2. Depo nedir?

- Ortak proje klasörü
- Dosyalar, geçmiş, tartışmalar ve görevler aynı yerde
- README projenin giriş kapısıdır

## 3. Commit nedir?

- Kaydedilmiş değişiklik noktası
- Geri dönmeyi ve ne değiştiğini anlamayı sağlar
- İyi commit mesajı kısa ama açıklayıcıdır

Örnek:

```text
Katılımcı profilini ekle
```

## 4. Branch nedir?

- Ana işi bozmadan çalışma alanı
- Deneme yapmayı güvenli hale getirir
- İş bitince pull request açılır

## 5. Pull request nedir?

- Değişikliği ekibe gösterme alanı
- Tartışma, kontrol ve onay burada yapılır
- Review kültürü burada başlar

## 6. Issue nedir?

- Yapılacak iş, hata, soru veya karar kaydı
- Dosya değişikliğinden önce işin tarif edilmesini sağlar
- Küçük ekiplerde bile düzen kazandırır

## 7. Review nasıl yapılır?

- Kibar
- Somut
- Satıra bağlı
- Gerekçeli

Kötü yorum:

```text
Burası yanlış.
```

Daha iyi yorum:

```text
Bu cümlede neyin tamamlandığı belli değil. Bir örnek ekleyebilir misin?
```

## 8. Conflict nedir?

- İki değişiklik aynı satıra denk gelmiştir
- GitHub hangisinin kalacağına tek başına karar veremez
- İnsan kararı gerekir

## 9. İyi ekip alışkanlıkları

- Küçük değişiklik
- Açık commit mesajı
- PR açıklaması
- En az bir review
- Issue ile iş takibi

## 10. Bugünkü hedef

Atölye sonunda herkes:

- bir dosya eklemiş olacak
- branch kullanmış olacak
- pull request açmış olacak
- review yapmış olacak
- conflict görmüş olacak
