03

DECISION RULE

Is Git necessary?

Git is not mandatory for every file. But if history, teamwork or safe experiments matter, starting early saves pain.

Use it

For code, reports, circuit diagrams or analysis files that will change and may need rollback.

Not always

For one-off throwaway files, Git may add learning overhead without much benefit.

Be careful

Passwords, API keys, personal data and huge raw files do not belong directly in the repo.

The question is not “Do we know Git?” The question is “Do we need history, collaboration and safe experiments?”

TWO DIFFERENT THINGS

Git vs GitHub

GIT

The tool on your laptop

  • Tracks every change to your files
  • Keeps a full history you can rewind
  • Merges teammates' work safely
  • Runs locally, even offline

Like a camera: it takes snapshots of your project.

GITHUB

The website in the cloud

  • Hosts your repositories online
  • Issues, pull requests, project boards
  • Access control for your team
  • A public portfolio of your work

Like a shared album for those snapshots.

GitHub is built on Git — you use both together.

PART 1 · HABITS

What stays out of the repo

Secrets

Wi-Fi passwords, API keys, tokens. Once pushed to a public repo, treat them as leaked.

Build output

Compiled .hex and .bin files, .pio/, __pycache__/ — they can be rebuilt from source.

Huge binaries

Videos and large CAD assemblies bloat history. Use Git LFS, or attach them to a Release.

# .gitignore

.pio/

build/

*.hex

secrets.h

Reading a diff

− Uses an Arduino Uno.

+ Uses an ESP32 DevKit.

Read the diff before you merge — every time, even your own.

19

PART 2 · COLLABORATION

Merge conflicts: don't panic

// firmware/main.ino

<<<<<<< HEAD

const float Kp = 1.4;

=======

const float Kp = 1.8;

>>>>>>> feature/pid-tuning

What happened? Two people changed the same line differently; Git can't decide which one is right.

1 · Which value is correct? Ask the team, or test on the robot.

2 · Delete the markers, keep the right line.

3 · Save, commit, push.

Prevention: pull often, keep branches small, don't edit the same file at the same time.

PART 3 · GROUND RULES

Using AI responsibly

You own it

Every line you merge is your responsibility, whoever wrote it.

Understand, then merge

Can't explain it? Ask the agent to explain, or don't merge it.

Test on hardware

The agent can't see your robot. Run it on the real system.

No secrets in prompts

Never paste passwords, API keys or personal data.

Be transparent

Say in the PR what the AI did; keep its Co-authored-by lines.
